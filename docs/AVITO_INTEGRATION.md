# Avito: фактическое состояние

Источник сейчас намеренно отключён. AvitoProductProvider наследует UnavailableProductProvider: products=[], sourceAvailable=false, error=not_configured, отдельный товар null. Выбор централизован в backend/src/services/products.ts. Credentials сами по себе не включают сеть. Никаких fake/demo-товаров в приложении.

В backend/src/providers/avito/oauth-client.ts подготовлен серверный client_credentials запрос к POST https://api.avito.ru/token: URLSearchParams, timeout 10s, запрет redirects, обязательный access_token/expires_in, in-memory token cache с запасом истечения и дедупликацией. Класс не создаётся production-provider и не читает env автоматически. Реальный OAuth не проверялся; тесты используют только внедрённый транспорт. Токен не возвращается REST и не хранится в браузере/файлах.

Официальная документация https://developers.avito.ru/api-catalog при проверке перенаправила на www.avito.ru/developers/api-catalog и вернула 403 «проблема с IP». Это ограничение документации, не вывод о доступности API. Обход не предпринимался. Item API не реализован вслепую: не подтверждены права, фактический контракт GET /core/v1/items, пагинация, описания/фото и лимиты. Существующая normalization.ts — защитная функция, не утверждение о реальном формате API.

Кеш каталога в памяти: 600 секунд, дедупликация, ограниченный stale; перезапуск очищает его. Недоступный результат сохраняет sourceAvailable=false. Нет Redis/БД.

## Подключение после получения доступа

1. Получить официальную актуальную спецификацию/права и подтвердить ответы OAuth и Item API без логирования токенов.
2. Вручную заполнить backend/.env по backend/.env.example. .env.local не перемещать и не публиковать. Проверка имён в нём была заблокирована инструментом; содержимое не читалось.
3. Реализовать AvitoProductProvider по подтверждённому контракту: запросы, пагинация, ограничение времени, обработка 401/403/429, getProductById, нормализация только активных объявлений и safe URL. Не считать снятый товар проданным.
4. Подключить OAuth-клиент и кеш; протестировать реальные поля/фотографии/ссылки, затем включить provider явно. UI и REST-контракты переписывать не требуется.
5. Задать SITE_URL/VITE_SITE_URL и оценить prerender товарных страниц для SEO.

Ограничения: нет подтверждённых реальных товаров, фото и цен API, нет проверки живого OAuth/Item API. Сайт честно показывает недоступность, а не успешный пустой каталог.
